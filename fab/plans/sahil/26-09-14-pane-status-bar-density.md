## Decisions of record

- **The five signal registers stay orthogonal** (`out`/`agt`/`fab`/`pr`/`opr` — spec § Row Minimalism, decided). Nothing in this plan merges, drops, or reorders a register. Every change below acts on the *values* a register renders, on the identity rows (`tmx`/`cwd`/`git`, pane metadata, not registers), or on which *surface* renders the view.
- **The change slug is written once.** The branch of a fab pane is the change folder name (`260913-png4-compose-default-on`), so the `git` row already carries id + slug. `getFabLine` / `getFabParts` gain a `branch` argument and omit the slug when the branch ends with `<id>-<slug>`; when the branch does not carry the change (`main`, a hand-named `t7vy-launch`), the slug stays — and its presence beside a branch row becomes the signal that the pane is off its change branch (the situation the `git-pr` branch guard trips on). The shared resolver owns the rule, so the PANE panel, the row flyout card, and the status bar cannot disagree.
- **`tmx` shows the pane id; the ordinal only disambiguates**: `%107` for a one-pane window, `%107 · 2/3` for multi-pane. The ordinal is the active pane's **position in `win.panes`** (1-based), never `paneIndex + 1` — tmux's `#{pane_index}` already honours `pane-base-index` (this host: `1`), which is why today's panel reads `pane 2/1` for a single pane. Change 0 fixes the arithmetic under the current `pane n/m` grammar; change 1 switches the grammar.
- **`cwd` is basename-first in the panel; the parent yields.** The worktree name is the answer and must never be the part that truncates. The bar keeps its basename-only form.
- **L0 says `flowing`, L1 says `active`.** `out` becomes `<cmd> · flowing` / `<cmd> · idle Xm` (no "since last output" narration — the tier-1 tip carries it). "flowing" is the spec's own word for L0 (§ Duration-Text Ladder: *L0 reads "flowing"*). The L1 vocabulary (`active`/`waiting`/`idle`) is written by harness hooks and read cross-repo (`agent-state.md`) — **not ours to rename**. Wire values (`activity: "active" | "idle"`) are untouched; this is render-only.
- **The status bar's CSS breakpoint ladder is replaced by a measured priority fold.** Overflow is caused by *value* length (30-char branches, 48-char fab lines), not viewport width; at 1512 px nothing has dropped yet and six segments truncate proportionally. The fold is the fourth instance of the shipped measured-overflow idiom (`lib/top-bar-overflow.ts` `computeVisibleCount`, `lib/crumb-collapse.ts`, `lib/gui-toolbar-fold.ts`): every segment renders at natural width or folds into the `…` menu; truncation is reserved for the single lowest-priority survivor when the never-fold set alone does not fit. One ladder across both clusters, so the two sides stop competing.
- **The version fragment becomes its own segment** (today it shares one truncating span with the host name and vanishes by truncation long before its documented < 700 px drop — the memory and the DOM disagree). Fixed in change 0 within the current ladder; change 2 then gives it a fold priority.
- **PANE-on ⇒ the bar's window cluster yields.** The bar's left cluster exists because the desktop PANE panel was retired; when a desktop viewer opts the panel back in *and the sidebar is open*, the bar passes `window={null}` and keeps only the host cluster. **Deviation from the study**: the study kept the `pr` segment while yielding; the plan drops the whole cluster. Reason: keeping `pr` needs a new `StatusBar` prop and a `WindowCluster` branch, which puts change 3 on the same file change 2 rewrites and forces the ladder serial; the panel shows the `pr` row with its open-first `↗` directly in the sidebar, so the bar's copy is redundant there. If the `pr`-keep is wanted after all, it is a follow-up on top of 2.
- **Hiding the tmux status line** for rk-managed servers stays **parked** (as in the quake-terminal plan, row 6): tmux `status` is a session option, so a local `tmux attach` loses it too; outside the two surfaces this plan is about.
- **Rejected** (recorded in the study § F): collapsing the registers into one line; a settings surface for which bar segments show (Constitution IV — one registry-driven settings surface, VII — the fold is the convention); horizontal scroll or a two-row bar; dropping the `git` row when it equals the change (takes away the most-copied row); yielding the bar whenever the sidebar is open (the default desktop has the sidebar open and the panel off); renaming the agent-state vocabulary.

## Change 0 — pane ordinal + version segment (slug: `status-bugs-ordinal-version`)

**Intake seed**: Two status-surface bugs — the PANE panel and status bar read `pane 2/1` for a single pane under `pane-base-index 1`, and the bar's version fragment truncates away with the host name instead of dropping at its ladder step.

1. **`getTmxLabel(win)` in `registers.ts`** (new; the PANE panel's identity-row source moves next to the resolvers so three sites share one string): ordinal = `win.panes.findIndex(p => p.isActive) + 1` (fallback: first pane), count = `win.panes.length`, returns `pane <ordinal>/<count>[ <paneId>]` — today's grammar, correct arithmetic. Replace the three inline compositions: `status-panel.tsx` (`activePaneIndex + 1`), `status-bar.tsx` `WindowCluster.tmxValue` and `OverflowMenu.tmxRest`. Copy value stays `paneId`.
2. **Version as its own segment** in `status-bar.tsx`: split the `(hostName || version)` span into two siblings — host button `min-w-0 truncate`, version button `shrink-0 hidden min-[700px]:inline` — so the version drops at its documented step instead of truncating first. The overflow `version` row is unchanged (`min-[700px]:hidden`).
3. **Tests**: `registers.test.ts` — `getTmxLabel` with `paneIndex` starting at 1 (one pane ⇒ `pane 1/1 %107`; three panes, active third ⇒ `pane 3/3 %109`), with no `paneId`; `status-panel.test.tsx` + `status-bar.test.tsx` fixtures gain a `paneIndex: 1` single-pane case asserting `1/1`; `status-bar.test.tsx` asserts host and version are separate elements and the version element carries the 700 px class. E2e `status-bar.spec.ts` `pane 1/1 %1` assertions stay valid (fixture `paneIndex 0`, one pane ⇒ ordinal 1) — no e2e change expected; run `just test-e2e status-bar.spec` to confirm.
4. **Memory**: sidebar.md § WindowPanel ("`tmx` (pane index + ID)" → ordinal position, robust to `pane-base-index`); status-signals § Status Bar right-cluster sentence (`<host> v<version>` → two fragments, version drops at 700).

## Change 2 — status bar measured fold (slug: `status-bar-priority-fold`)

**Intake seed**: The status bar folds by measured priority instead of CSS breakpoints — every segment renders at natural width or moves to the `…` menu, one ladder across both clusters, `cpu · mem` as percents with `ld` its own segment — so the bar never shows six ellipses.

1. **`lib/status-bar-fold.ts`** (new, pure; header names the three precedents): `computeStatusBarFold(items, availablePx, prev)` over items in display order `{ id, widthPx, prio: number | null }` (`null` = never folds). Fit rule: charge `PAD 16 + dot 8 + gap 12` and `12 px` between rendered items per cluster; while over budget, fold the lowest `prio` item (ties: rightmost first). **Two-pass reserve** (the gui module's rule): fit once with no `…` reserve; if anything folds, refit with the chevron's measured width reserved. **Last-survivor truncation**: if the never-fold set alone overflows, return `truncateLast: true` and the component gives the lowest-priority survivor `min-w-0 truncate`. One-sided expand hysteresis `STATUS_BAR_FOLD_HYSTERESIS_PX = 24`; unmeasured widths (0) ⇒ return `prev`; cold default fully expanded. This is a *priority* fold (any position), not the gui module's suffix fold, so it is a sibling module rather than a generalisation — the plan's intake may still choose to extract shared pieces (hysteresis, two-pass) if the diff stays small.
2. **Priority table** (display order stays branch-first — decided): left `⑂ 9 · pr never · fab never · agt 8 · tmx 3 · cwd 2`; right `zen ✕ never · cpu·mem 6 · ld 0 · ◷ next 4 / ◷ stale never · server 5 · host 10 · version 7 · ⌘K 1 · a▏ 1 · … (reserve) · connection dot never`. Lower dies first.
3. **Component** (`status-bar.tsx`): one `ResizeObserver` on the bar + a hidden probe row rendering every candidate segment at natural width (the top-bar / gui idiom); measure on mount, on resize, and when the window record / metrics / version / clock state change identity. Segments drop every `min-w-0 truncate` and breakpoint class; rendered segments are `shrink-0`. **Metrics get fixed-width numerals** (`tabular-nums` + a `min-w-[Nch]` reserve for `cpu NN%` / `mem NN%`) so the 2.5 s metrics tick does not re-fold the bar. Collapse-first: null initial fold state renders nothing foldable until the pre-paint measure (the gui rule), so the bar never paints wide then snaps.
4. **Metrics diet**: `cpu N% · mem N%` (mem as a percentage in `gaugeColor`), `ld N%` its own segment; `MetricsFlyout` unchanged (the shared `HostMetrics` has the absolute values and graphs).
5. **`…` menu**: rows are the folded ids in strip order (same row kinds — copy-action buttons for git/tmx/cwd/version, informational spans for metrics, action rows for ⌘K / compose / ◷); the chevron renders iff anything is folded (today it is `xl:hidden` unconditionally). Keyboard contract (`top-bar-overflow-menu.tsx`'s: focus in on open, ArrowUp/Down rove, Escape returns to the chevron) unchanged; drop the `checkVisibility` filter (no hidden rows remain).
6. **Clock chip**: `hidden xl:flex` → prio 4 when `next`, `null` when `stale`; the overflow `clk` row rides the fold like any other.
7. **Tests**: `lib/status-bar-fold.test.ts` — the ladder order, ties, never-fold, two-pass reserve, last-survivor truncation, hysteresis (expand needs +24), unmeasured keeps prev. `status-bar.test.tsx` — replace the six breakpoint-class assertions with fold-state assertions using the gui-toolbar harness (ResizeObserver stub + `getBoundingClientRect` widths per probe item); keep the copy/flyout/click-seam/coalesced-hooks tests. E2e `status-bar.spec.ts` — the width-sweep case is rewritten: the fixture's short values (`wt`, `%1`) would fit at 800 px and fold nothing, so either give the fixture a 30-char branch + a fab line or sweep to 640 px; assert the `…` menu lists `tmx` and `cwd` when folded and that a folded copy row still copies on Enter (the existing keyboard case, re-pointed). Intent comments updated.
8. **Memory**: status-signals § Status Bar — rewrite the *Overflow* bullet (ladder → fold, the priority table, two-pass reserve, last-survivor rule, fixed-width numerals), the clock-chip class sentence, the right-cluster text (`cpu N% · mem N%`, `ld` own segment), the *Coverage* bullet; rewrite the three Design Decisions that name breakpoints (*Status-bar left cluster is branch-first descending relevance* — display order stays, survival order is now the priority table; *The `out` register leaves the status bar* — unchanged rationale, drop the "rides the bar to 640px" phrasing; *Stale clock chip survives the ladder* → *never folds*) and add *A measured priority fold replaces the breakpoint ladder*. `architecture/repo-layout.md` if it enumerates `lib/` modules (check `gui-toolbar-fold` there — it is cited from `gui.md` and `lenses-and-layout.md`, not repo-layout). Update the `status-bar.tsx` header comment (the OVERFLOW block).

Non-goals: mobile (renders no bar); adding or removing segments (the set is fixed — server folds, it does not disappear); the flyout content; the PANE-on gate (change 3).

## Change 3 — PANE-on yields the bar; continuation lines (slug: `pane-panel-yield-continuation`)

**Intake seed**: With the PANE section opted in on desktop, the status bar hands the window registers back to the sidebar and keeps only its host cluster; the panel's `pr` and `fab` rows wrap their tail onto a dim continuation line instead of truncating.

1. **Mount gate** (`app.tsx` at the terminal-route `StatusBar`): `const [paneSectionVisible] = useSidebarSectionVisible("pane")` + `sidebarOpen` from `useChromeState()`; `window={paneSectionVisible && sidebarOpen ? null : currentWindow ?? null}`. Both hooks are localStorage-backed pub/sub, so the bar flips live when the rail toggle or `Panel: Toggle Pane` fires, and comes back when the sidebar collapses (`Cmd+\`) — the panel is then not visible, so the bar is again the only register view. Board (`window={null}` already) and Host mounts: no change. Mobile is unaffected (no bar). No `StatusBar` prop or `WindowCluster` change (the reason 2 ∥ 3 is safe).
2. **Continuation lines** (`status-panel.tsx`): `pr` — key line `#<n> · <state> ↗`, continuation `checks <c> · review: <r>` (coloured segments kept, `text-text-secondary` separators), indented 4 ch under the value column, `truncate`; the anchor wraps both lines so open-first covers the whole block; the hover-revealed copy icon stays on the key line. `fab` — key line `<id> · <stage> · <state>`, continuation `<slug>` **only when `getFabParts(win, branch)` returns a slug** (the branch does not carry it). Consider lifting the flyout card's fab composition into a small shared piece so the two surfaces compose identically. A row never exceeds two lines. Test ids: `pr-line` stays on the key line; add `pr-line-cont` / `fab-line-cont`.
3. **Tests**: `status-panel.test.tsx` — continuation present/absent for pr (open with checks+review vs merged) and fab (slug carried vs not); the anchor spans both lines. `app.test.tsx` (or the shell test that mounts `StatusBar`) — `status-bar-window` absent when the pane section is visible and the sidebar open, present when either is false. E2e in **`pane-register-panel.spec.ts`** (not `status-bar.spec.ts`, which change 2 rewrites): toggle the Pane section on via the palette on desktop ⇒ `status-bar-window` count 0; toggle off ⇒ visible; collapse the sidebar with the panel on ⇒ visible.
4. **Memory**: sidebar.md § Collapsible Panels (desktop opt-in now yields the bar's window cluster; the register view has one desktop home at a time) and § WindowPanel (two-line rows); status-signals § Status Bar (one gate sentence in the left-cluster bullet — the sentence change 2 also touches) and § Pane panel five-register view (continuation rule, mirroring the card).
